01Introduction

This Privacy Policy explains what information Quello (“Quello”, “the Bot”, “we”, “us”, or “our”) may process when installed on or used within a Discord server. We aim to collect and retain only information reasonably necessary to provide the Bot’s features.

02Information We Process

Core Bot data

The Bot may process Discord User IDs, Server (Guild) IDs, Channel IDs, Message IDs, and QOTD IDs, including:

  • QOTD records — the question, creator, QOTD number, language, creation date and time, server ID, channel ID, message ID, and the ID of the related discussion thread.
  • Server configuration — role IDs, channel IDs, QOTD settings and counters, the bot interface language, the lock and maintenance states, the allowed role ID, the optional mention role ID, and the @everyone and @here mention settings.
  • Normal QOTD logs — action type, user ID, related QOTD ID, additional action details, and date and time. Changes made through /config are recorded here.
  • Audit log — interaction type (such as slash command, button, dropdown, or modal), command or component name, status, user ID, channel ID, additional details, and date and time. Audit records are kept separately from normal QOTD logs and are not removed by /reset_logs.
  • Interaction IDs — kept briefly to prevent duplicate actions.

Discussion threads

For messages posted in a QOTD discussion thread, Quello records the author’s User ID, the message ID, the channel ID, and the date and time so that answers can be counted for statistics and leaderboards and audited, including edits and deletions.

The text of those messages is not stored.

Question suggestions

When a member submits a question with /suggest, Quello stores:

  • the suggested question and its language;
  • the submitter’s User ID;
  • the suggestion’s status (pending, approved, rejected or deleted by its author);
  • the reason a moderator gives when rejecting it, and the reviewer’s User ID;
  • the date and time of submission and review.

Quello sends the submitter a direct message with the decision (the rejection reason, or a link to the published QOTD); if the member’s direct messages are closed, nothing is sent. If a suggestion is published, the QOTD record keeps the ID of the member credited as its suggester.

Statistics

Personal statistics shown by /me and /question_week are calculated from the records described above.

Achievements and progress

Quello stores each achievement unlocked by a member on a server and the unlock date. Achievement progress is calculated from unique QOTD participation records and UTC answer streaks. Server administrators can enable or disable achievement categories, and each member can turn achievement-unlock direct messages on or off. Achievement tracking does not store the text of discussion messages.

Public Global Leaderboard

The public Global Leaderboard displays your Discord display name and avatar together with your QOTD creation count, answer count and current answer streak. Rankings combine records from all servers using the same Quello database and can be viewed without signing in. QOTD message text is not displayed.

Website dashboard

If you sign in to the website dashboard with Discord, Quello receives your Discord User ID, display name, and avatar through the identify scope, and requests the guilds scope to read your server list and permission flags. It uses those flags to identify servers where you are the owner or have Administrator permission. It does not request your email, password, or message history. The Discord access token is used for these requests and then revoked on a best-effort basis.

Your User ID and the Discord server permission flags returned for your account are used to determine Dashboard eligibility. The Bot separately checks your User ID, server ownership, Discord Administrator permission and configured allowed role as required by each feature. Dashboard authorization and slash-command authorization are separate checks; access to the Dashboard does not automatically grant every slash command.

  • In the website Dashboard, the server owner, a Discord Administrator, or the Bot Owner can complete initial setup, view and change server settings, manage Scheduled QOTD, use maintenance and lock controls, publish and edit QOTDs, review suggestions, and access the server’s activity and audit logs.
  • Members with the server’s configured allowed role can view settings, publish and edit QOTDs, review suggestions, and view leaderboards and statistics. This role does not grant permission to change server-wide settings.

Your profile details are kept in a signed session token stored in your browser until it expires (7 days by default) or you log out; the Bot database keeps only a session record for this purpose (see “Dashboard sessions and Technical Work Mode”). The website also keeps your language and theme choices in your browser.

Changes made from the dashboard (including initial setup, publishing, editing, approving or rejecting) are recorded in the normal QOTD logs and the audit log with your User ID and are marked as made from the web, like the same actions made with slash commands.

03How We Use Information

Information is used to provide QOTD functionality, history, statistics and leaderboards, normal QOTD logs, detailed interaction auditing, permission controls, server configuration, maintenance and lock features, troubleshooting, and protection against abuse or unauthorized use.

We do not sell or use this information for advertising.

04Message Content

Quello may process message content directly submitted through its commands when required to perform the requested action, such as creating or editing a QOTD. For example, a QOTD question may be stored for history or authorized editing. The Bot does not intentionally collect unrelated private messages for purposes unrelated to its functionality.

05Data Storage

Quello uses a database to store information required for its features. The current implementation uses SQLite, and the database is backed up automatically once a day. Access is limited to the developer and the Bot’s infrastructure as reasonably necessary to operate and maintain the service.

06Data Sharing

We do not sell or rent information processed by Quello. Information may be processed through Discord’s services and APIs as necessary for the Bot to operate. We may disclose information when reasonably necessary to comply with law, protect security, investigate abuse or unauthorized access, or protect rights and safety.

07Data Retention

Information is retained for as long as reasonably necessary to provide the Bot’s functionality. QOTD history and administrative logs may be retained longer when required for history, statistics, administrative, or security features.

  • Automatic database backups are rotated, and only the most recent seven daily backups are kept.
  • Interaction IDs used to prevent duplicate actions are removed after about 30 days.
  • Deleting a QOTD with /delete removes its record and its recorded answers from the active database.

Public-profile visibility settings remain stored when a profile is made private. Disabled Server Discovery listings are removed from the public directory, but their saved settings remain stored. Feedback items and replies remain in the database while managed by the service; the current implementation does not define an automatic expiry period for them.

08Data Deletion Requests

Users may contact the developer regarding information associated with their use of Quello. Server administrators may request deletion of data associated with their server. Requests may require sufficient information to identify the relevant data. Some information may be retained when necessary for security, legal, or legitimate operational purposes.

09Security

We use reasonable technical measures intended to protect stored information. However, no method of electronic storage or Internet transmission can guarantee absolute security.

10Third-Party Services

Quello operates through Discord and uses Discord’s API and services. Discord is a separate third-party service with its own policies. Quello does not control how Discord processes information within its platform.

The website is hosted on GitHub Pages, and the dashboard API may be reached through a connectivity provider such as Cloudflare. These services can process technical request data (for example IP address, browser information and request times) as part of delivering the website and API, under their own policies. Quello does not use this technical data for advertising.

11Children’s Privacy

Quello does not intentionally request sensitive personal information. Users should not provide passwords, payment information, government identification documents, home addresses, or other sensitive information to the Bot.

12Changes to This Privacy Policy

This Privacy Policy may be updated from time to time. The Last Updated date will be changed when appropriate.

13Contact

For questions about this Privacy Policy, data processing, or deletion requests, please contact the developer through the Bot’s official support channel.

14Dashboard OAuth permissions

Dashboard sign-in uses Discord OAuth2 with the identify and guilds scopes. Quello reads your basic profile and the list of servers and permission flags Discord returns, then keeps only server IDs where you are the owner or have the Administrator permission. This is used to show eligible servers and check access. The OAuth access token is revoked on a best-effort basis after the required data is read.

The signed dashboard session contains your user profile and the eligible server IDs so the API can enforce server access. The session is stored in your browser and expires according to the configured session lifetime (7 days by default).

15Scheduled QOTD and AI provider

When Scheduled QOTD is enabled, or an authorized member runs /random_qotd, Quello uses the server’s configured bot language (English or Russian) and recent QOTD question text to prepare a prompt for question generation. The generated question is saved temporarily as a pending item until publication succeeds or the retry window ends.

The prompt and recent-question context are sent to Groq through its API to generate a question. Groq is an independent third-party service and processes the submitted request under its own terms and privacy practices. Do not enable this feature if your server’s recent QOTDs contain information that should not be sent to an external AI provider. Quello’s prompt asks for one short, original, witty and sometimes provocative question and tells the model to avoid clichés and repeats of recent questions. It does not filter the recent-question context before sending it, so server owners remain responsible for what is sent.

For temporary generation or publication errors, Quello retries every five minutes for up to one hour. Non-retryable API errors, including authentication, permission, or invalid-model errors, are not retried for the same slot; the slot is skipped and the server owner is notified. After repeated temporary failures, Quello also attempts to notify the server owner by direct message in English.

16Automated decisions and controls

The /random_qotd command can also trigger an immediate AI-generated QOTD for an authorized member. Scheduled QOTD does not make decisions about individual members. Server owners can enable or disable the feature, set its first local publication time and IANA time zone, and choose a recurring interval of every 1, 6, 12 or 24 hours in the Dashboard. Authorized QOTD managers can also run /random_qotd for immediate AI generation and publication.

17Discord Developer Team metadata

The bot requests the application’s Developer Team information from Discord through the application information endpoint. It uses the team owner ID and the listed members’ roles (Admin, Developer or Read Only), user IDs and membership states (accepted or invited) to decide who may use the Admin Panel, and for aggregate startup diagnostics.

When you use the Dashboard, your Discord User ID is compared with the Bot Owner ID and with this team information; the verified Team Owner and accepted Admin and Developer members receive Admin Panel access. Results are cached in memory for a few seconds. Team member IDs and names are not written to logs or saved in the database; diagnostics contain aggregate counts and verification status only. The Admin Panel shows authorized users the team’s member names, roles and invitation status as returned by Discord; these are not stored.

18Global announcement data

When an authorized Admin Panel user (Bot Owner, Team Owner, Admin or Developer) creates a global announcement, Quello stores the announcement content and optional embed fields, the creator’s Discord user ID, and the Discord guild, channel and message IDs for each successful delivery. The content is sent to Discord and is visible to members who can access the destination channel; Discord controls channel visibility. Delivery status and limited error type information may also be stored so the Admin Panel can display delivery results and manage the published copies. This information remains in the bot database while the announcement is managed. Deleting an announcement through the Admin Panel removes its published messages where Discord permits and deletes its stored campaign and delivery records when all deletions succeed.

19Dashboard sessions and Technical Work Mode

When you sign in to the Dashboard, the Bot database stores a session record: a session ID, your Discord User ID, display name and avatar hash, the creation and expiry times, and whether it was ended. It is used so that a session can be ended before it expires, and it is deleted once it has expired or been ended. Authorized Admin Panel users can list active sessions and end a single session or all sessions of a user.

Technical Work Mode stores only an on/off flag, the reason text entered by the authorized user, an optional end time and the time of the last change. The reason is shown to people who are blocked while the mode is on, so it must not contain personal data.

20Daily publication limit

To enforce the one-QOTD-per-server-per-UTC-day limit, Quello uses the Discord server ID and the UTC date/time already stored with each published QOTD. The check is performed separately for each server; local time zones are ignored, and the limit resets at 00:00 UTC. All members share the same daily allowance on their server, and there is no owner bypass. Manual, scheduled, random and approved-suggestion publications all use this same server-wide limit.

No separate profile, location, or message-content data is needed to calculate this limit.

21Public profiles, Server Discovery and Feedback Center

QOTD categories

Server-specific QOTD categories are stored with the server ID, category name, creator’s Discord User ID and creation time. Published QOTDs may reference a category ID. Category names are used to organize questions and are not displayed as personal profile data.

Public profiles and Discord profile banners

The banner image is retrieved from Discord when available; Quello does not upload or create a separate copy of the image. Where supported, the same banner may be used as the background of a user card in the Dashboard, Admin Panel, public profile or leaderboard. If no banner is available, the existing default card or profile background is used.

You can make your profile private and control whether answers, created questions and achievements are shown. When a profile is made private, its public endpoint stops returning the profile. Your privacy settings remain stored so you can change them later.

Opt-in Server Discovery

Server Discovery is optional. A server owner or Discord administrator can enable or disable a public server listing. For a listing, Quello stores the server ID, description, category, invite URL, the Discord User ID of the person who last changed it and the update time. While enabled, the public directory may display the server name, icon, member count, description, category and invite URL. Disabling a listing removes it from the public directory, but its saved listing settings remain in the database.

Feedback Center

When you submit feedback while signed in, Quello stores your Discord User ID and display name, the feedback category, title, description, status and creation/update times. Replies are stored with the author’s User ID and display name, whether the author is a Quello team member, the reply text and its time. You can view your own feedback items; authorized Quello team members can view feedback across users, reply and update its status. Do not include passwords or other sensitive information in feedback.

Questions? Contact the developer through the Bot's official support channel.
